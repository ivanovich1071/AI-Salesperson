# Тестирование UI/UX — план и запуск

Автоматические E2E-тесты сайта ВайбМайнд на **Playwright**: проверяют пользовательские
сценарии (переходы, кнопки, плашки, модалки, стрелки, адаптив) в реальном браузере.

> Статус: набор внедряется. Отмечайте по мере готовности — чек-лист в разделе 8.

---

## 1. Зачем

Раньше каждая правка проверялась только глазами, и регрессии находил заказчик:
«отвалившиеся» стрелки в блоке «Как мы работаем», наезжающий навбар на ~950px,
контраст бирюзового текста 2.66 при норме 4.5. Тесты ловят такое до деплоя.

---

## 2. Как запускать

```bash
npm run test:e2e          # полный прогон + HTML-отчёт
npm run test:e2e:ui       # интерактивный режим: видно каждый шаг, удобно смотреть глазами
npm run test:e2e:update   # обновить визуальные эталоны после намеренных правок дизайна
npm run test:e2e:live     # дымовой прогон по ЖИВОМУ AI (платно, вручную)
```

Отчёт открывается сам; повторно — `npx playwright show-report`.
У упавших сценариев внутри отчёта есть **видео и пошаговый разбор** (Trace Viewer).

Первый запуск на новой машине:

```bash
npm install
npx playwright install chromium
```

Dev-сервер поднимать не нужно — Playwright запускает его сам (`webServer` в конфиге)
и гасит после прогона.

## 3. Что установлено

| Пакет | Роль |
|---|---|
| `@playwright/test` | Ядро: браузер, авто-ожидание, перехват сети, эмуляция устройств, скриншот-эталоны, Trace Viewer |
| `@axe-core/playwright` | Аудит доступности: контраст, подписи полей, роли, alt |

Юнит-тестов (Jest/Vitest) сознательно нет: E2E покрывает сценарии ближе к реальности.
Отдельной задачей стоит покрыть чистую бизнес-логику — `calculateTrainingCost`
(`src/lib/pricing.ts`) и `selectProgram` (`src/lib/moduleSelection.ts`).

## 4. Три особенности проекта, которые определяют тесты

**4.1. AI-роуты мокаются.** Шесть из одиннадцати API ходят в OpenRouter
(`chat`, `proposal`, `objection`, `extract-company`, `extract-diagnostics`, `transcribe`):
8–30 секунд, платно, каждый раз разный текст. На живом AI тесты были бы медленными,
дорогими и «мигающими». Хелпер `mockAi(page)` перехватывает `**/api/ai/**` и отдаёт
фикстуры. Формы ответов берутся из `src/lib/schemas.ts`, чтобы мок не разошёлся с продом.

> Живой AI проверяется отдельно: `npm run test:e2e:live` (тег `@live`).
> В общий прогон и в деплой не входит.

**4.2. Отдельная тестовая база.** Бронь требует свободных слотов, а тесты создают брони
и карты диагностики. Используется `DATABASE_URL=file:./test.db`: `globalSetup` применяет
схему и засевает слоты через существующий `scripts/seed-slots.mjs`.
**Рабочая база `prisma/dev.db` не трогается.**

**4.3. Голосовой ввод — частично.** Микрофона в тестовом браузере нет: Chromium
запускается с `--use-fake-device-for-media-stream`, `/api/transcribe` мокается.
Проверяется логика (запись → «Распознаём речь...» → текст в поле → фильтр галлюцинаций),
но **не качество распознавания** — это только вручную.

Плюс: визард хранит состояние в `localStorage` (`ai-salesperson-wizard`), поэтому каждый
тест стартует с `/app?new=1` или с очищенным storage — иначе тесты «заражают» друг друга.

## 5. Структура

```
playwright.config.ts          # проекты desktop/mobile, webServer, HTML-отчёт, видео при падении
e2e/
  fixtures/ai-responses.json  # заготовленные ответы AI
  helpers/
    mockAi.ts                 # перехват /api/ai/**
    adminAuth.ts              # логин админа один раз → storageState
    resetWizard.ts            # чистый старт визарда
  landing.spec.ts             # главная
  course.spec.ts              # /course
  wizard.spec.ts              # визард, все 6 экранов
  admin.spec.ts               # админка
  a11y.spec.ts                # доступность (axe)
  visual.spec.ts              # скриншот-эталоны
  smoke-live-ai.spec.ts       # @live, вручную
```

Прогон идёт в двух конфигурациях: **desktop** (1280) и **mobile** (Pixel 5, 375).

## 6. Что покрываем

**Главная:** якорная навигация · бургер-меню на мобильном · 7 карточек «Лаборатории» →
модалка (открытие, закрытие крестиком и по фону, ссылки на боты с `target="_blank"`) ·
CTA → `/course` и `/app?new=1` · телефон и `@vibemindpro` · футер · **стрелки процесса
между карточками, а не под ними** · нет горизонтального скролла на 375/768/950/1280 ·
навбар не наезжает на 950px · карточки одной высоты.

**Курс:** навигация · 4 модалки сертификатов · тизер → `/#solutions` · CTA в визард ·
личных контактов нет.

**Визард:** сквозной путь компания → анкета → предложение → бронь → успех ·
ветка возражения (3→4→5) · кнопки «Назад» · кликабельный степпер (назад свободно,
вперёд — только по готовности) · валидация формы · заполнение анкеты из чата ·
активность «Сформировать предложение» при ≥1 ответе · голосовой ввод · бронь слота ·
дружелюбные ошибки при сбое API.

**Админка:** неверный и верный логин · брони · карты диагностики · добавление и удаление
слотов · шаблон сообщения.

**Сквозное:** ноль ошибок в консоли · axe-аудит · визуальные эталоны (desktop + mobile).

## 7. Связь с деплоем

Прогон встроен в `scripts/deploy.sh` **до пуша**: тесты упали → деплой не стартует.
Срочная выкатка в обход — `npm run deploy -- --skip-tests`.

## 9. Что тесты НЕ покрывают

Честные границы: реальное качество распознавания речи, осмысленность ответов AI и
субъективную эстетику автоматика не проверяет. Это остаётся ручной приёмкой — но теперь
она про смысл и красоту, а не про «не отвалилась ли кнопка».
