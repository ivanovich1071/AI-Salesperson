# ВайбМайнд — AI-продажник корпоративного обучения

Единый сайт-приложение компании **ВайбМайнд**: лендинг компании (бирюзовый бренд), лендинг
корпоративного курса Вероники Пунчик «Нейросервисы и системы искусственного интеллекта: от
основ к экспертным решениям» + интерактивный AI-визард, который проводит клиента через
диагностику бизнес-задач, подбирает модули обучения, считает стоимость, отвечает на
возражения и записывает на встречу с экспертом.

## Стек

Next.js 14 (App Router) · TypeScript · Tailwind CSS (фирменная бирюза ВайбМайнд) · Zustand ·
SQLite + Prisma · OpenRouter (Qwen — текст/JSON, Whisper Large V3 — голос).

## Быстрый старт

```bash
npm install
cp .env.example .env       # заполнить OPENROUTER_API_KEY и остальные переменные
npm run db:push            # применить схему Prisma к SQLite
npm run dev                # http://localhost:3100
```

## Тесты

**136 E2E-сценариев** на Playwright: переходы, кнопки, модалки, адаптив, доступность,
расчёт цен и визуальные эталоны — в реальном браузере, на десктопе и мобильном.

```bash
npx playwright install chromium   # один раз на новой машине
npm run test:e2e                  # прогон + HTML-отчёт с видео падений
npm run test:e2e:ui               # интерактивный режим
```

Тесты работают с **отдельной базой** (`test.db`) и **замоканным AI** — рабочие данные
не засоряются, живой OpenRouter не дёргается. Прод они не трогают: можно спокойно
пользоваться сайтом во время прогона.

Подробности, статус и открытые вопросы — в **[TESTING.md](TESTING.md)**,
соглашения для разработки — в `.claude/skills/testing/SKILL.md`.

## Деплой — в один шаг

Пароль от сервера вводить **не нужно** (вход по SSH-ключу). Двойной клик по файлу
**`Деплой.bat`** в папке проекта — или из терминала:

```bash
npm run deploy
```

Скрипт сам: запушит `main` → обновит код на сервере → поставит зависимости →
применит схему БД → соберёт → перезапустит сервис → проверит, что сайт отвечает.
Занимает 3–6 минут. Полная инструкция, разбор ошибок и восстановление доступа —
в **[DEPLOY.md](DEPLOY.md)**.

## Видимость в ИИ-поисковиках (GEO)

Сайт настроен так, чтобы ChatGPT Search, Perplexity, Claude, Gemini и Copilot
могли его обойти, понять и процитировать:

- `robots.txt` разрешает 18 ИИ-краулеров поимённо (GPTBot, ClaudeBot,
  PerplexityBot, Google-Extended, Bingbot и др.), закрыты только `/admin` и `/api`;
- машиночитаемая идентичность: `llms.txt`, `llms-full.txt`, `identity.json`,
  `ai.json`, `/.well-known/ai.txt`;
- разметка Schema.org: Organization, WebSite, ItemList решений, Course, Person,
  FAQPage, BreadcrumbList;
- страница `/faq` с вопросами в формулировках пользователей — именно её цитируют
  модели, отвечая «где заказать внедрение ИИ в Беларуси».

Все факты — в `src/lib/seo/profile.ts` и `src/lib/seo/faq.ts`; остальное
собирается из них. Проверка после деплоя:

```bash
npm run geo:audit -- https://vibemind.by
```

⚠️ `NEXT_PUBLIC_SITE_URL` вшивается на сборке. Если в проде он не задан или
остался `localhost`, sitemap, canonical и JSON-LD уводят краулеров на локальные
адреса — сайт выпадает из выдачи. Аудит это ловит отдельной проверкой.

## База знаний и системный промпт

`knowledge/` — Obsidian-vault (можно открыть как vault в Obsidian). Все `.md`-файлы, кроме
`README.md`, автоматически подгружаются в системный промпт AI (см. `src/lib/knowledge.ts`).
Пополнение: положить новый `.md`-файл с числовым префиксом (`03-...`) — перезапуск сервера
не требуется в dev-режиме.

`prompts/assistant-system.md` — системный промпт консультанта (роли агентов, правила
безопасности, стратегия анкеты, сценарии возражений).

`knowledge/03-products-pricing.md` — продуктовая модель: уровни (обучение → лаборатория →
проектирование → разработка), учебные модули, сборки, документы по этапам.

## Диагностика (шаг 2)

Чекбокс-анкета, **фиксированная по роли** (не генерируется AI): `src/lib/diagnosticQuestions.ts`.
Организационные вопросы (текущее использование ИИ, внутренние документы, политика ИИ) —
общие для всех ролей; вопросы о рутинных задачах и процессах для ИИ-ассистентов —
адаптированы под каждую из 6 ролей (правятся в одном файле). У каждого вопроса есть
вариант «Другое» с текстовым и голосовым вводом.

**Заполнение через чат.** Пользователь может писать или диктовать ответы прямо в AI-чат —
`POST /api/ai/extract-diagnostics` разбирает сообщение и авто-отмечает подходящие варианты
анкеты (совпавшее → чекбоксы, остальное → свободные заметки для предложения). Кнопка
«Сформировать предложение» активна уже при **одном** ответе (чекбокс или через чат).

**Карта диагностики.** При формировании предложения сохраняется в БД (`DiagnosticMap`,
`POST /api/diagnostics`) и доступна в админке в разделе «Карты диагностики». «Соответствие
задачам» считается комбинированно: детерминированная формула в коде + оценка AI (не
захардкоженное число).

## Ролик о компании на главной

Секция «ВайбМайнд за 60 секунд» сразу под шапкой: `src/components/landing/VideoSection.tsx`,
файл — `public/video/vibemind-60s.mp4` (1080p, 60 с, 4,5 МБ), заглушка —
`public/images/video-poster.jpg`.

Сделано на нативном `<video>`, **без единой библиотеки**. Загрузка экономная:
`preload="none"` плюс постер — до того, как секция попадёт на экран, браузер тянет одну
картинку (~95 КБ), а не весь ролик. Автозапуск (без звука, зациклено) включается по
`IntersectionObserver`, только на десктопе и только когда секция реально видна; ушли со
секции — воспроизведение встаёт. На узком экране и при `prefers-reduced-motion` ролик ждёт
тапа: тратить чужой мобильный трафик без спроса невежливо.

Ролик отдаётся статикой через Next. Если нагрузка вырастет — вынести `/video/` в отдельный
`location` nginx (см. [ROADMAP.md](ROADMAP.md), раздел производительности).

## Пакеты и цены (детерминированно, не через AI)

Клиент покупает **готовый пакет из прайса**, а не набор модулей. Цена не складывается из
позиций: это опубликованный протокол, за который расчёт не имеет права выйти.

| Пакет | Состав | Часы |
|---|---|---|
| Знакомство | Б1 | 4 |
| Безопасный старт | Б1 + Б2 | 8 |
| Профессиональный | Б1 + Б2 + один профессиональный трек | 12 |
| Углублённый | Б1 + Б2 + два профессиональных трека | 16 |
| Для руководителей | РУК | 4 |
| Управление и внедрение | П1 + РУК | 8 |

Подготовка программы, практические материалы, итоговая оценка и экспертное заключение
**входят в цену пакета** и отдельными строками не выставляются. Сверху добавляются только
дополнительные потоки (каждые следующие 20 человек — дешевле первого проведения) и
отдельный контур руководителей.

Три предохранителя не дают смете разойтись с прайсом:

- **не больше двух треков** в программе (`MAX_AUTO_TRACKS`) — это потолок протокола. Всё,
  что анкета нашла сверх, уходит в блок «Можно добавить» с ценой за трек и **в сумму не
  входит**;
- **больше 60 человек** (`MAX_AUTO_STREAMS`) — точная сумма не показывается: клиент видит
  «от N BYN», такие программы собираются вручную;
- **потолок итога** (`MAX_AUTO_TOTAL`) — страховка от любого неожиданного разбега.

Где что лежит:

- `src/lib/pricing.ts` — единственное место правки цен: пакеты, надбавки, предохранители,
  каталог модулей **Б1, Б2, П1–П8, РУК** (по 4 ч). Поток = `ceil(участники / 20)`;
- `src/lib/moduleSelection.ts` — автоподбор по роли и сигналам из анкеты. AI модули не
  выбирает и цены не считает — только объясняет готовый выбор;
- `e2e/pricing.spec.ts` — контрольная матрица: все шесть пакетов дают ровно прайсовые
  цифры, а перебор комбинаций треков и численности не выходит за потолок;
- **Лаборатория AI-кейсов** — отдельный продукт (5 000–9 500 BYN), не суммируется с
  обучением. **Проектирование и разработка** — «стоимость после отдельной оценки задачи».

> Предложения, посчитанные по прежней помодульной схеме, сбрасываются при загрузке:
> в `wizardStore` поднята `version: 2` — иначе вернувшийся клиент увидел бы старую цену
> из `localStorage`.

## Уведомления в Telegram

Новая заявка на встречу и пройденная диагностика приходят сообщением в Telegram — в личку
или в общий чат. Раньше их было видно только тому, кто зашёл в админку.

Что внутри уведомления о брони: дата и время встречи, компания, имя, телефон, почта, роль,
число участников, расчёт стоимости, подобранные модули и ссылка на админку.

**Подключение — три шага, занимает пять минут:**

1. В Telegram напишите **@BotFather**, команда `/newbot`, придумайте имя и адрес бота.
   BotFather выдаст токен вида `123456789:AA...` — это секрет, его не коммитить.
2. Впишите токен в `.env` строкой `TELEGRAM_BOT_TOKEN=...`, найдите бота по адресу,
   нажмите «Запустить» и отправьте ему любое сообщение.
3. Узнайте свой `chat_id` и проверьте связь:

```bash
npm run telegram:setup
```

Скрипт покажет найденные чаты — скопируйте нужный id в `TELEGRAM_CHAT_ID` (несколько
получателей перечисляются через запятую). Проверка боем:

```bash
npm run telegram:test
```

На сервере те же две строки добавляются в `/opt/ai-salesperson/.env`, после чего
`systemctl restart ai-salesperson`.

Тонкости:

- **уведомления не могут уронить сайт**: если Telegram недоступен или токен не задан,
  бронь всё равно сохраняется, а в лог уходит предупреждение;
- сообщения уходят **в фоне** — клиент не ждёт ответа Telegram на шаге брони;
- уведомления о диагностиках (их больше, чем броней) отключаются флагом
  `TELEGRAM_NOTIFY_DIAGNOSTICS=off`;
- для общего чата с Вероникой: добавьте бота в группу, напишите там сообщение и снова
  запустите `npm run telegram:setup` — id группы появится в списке.

Код: [src/lib/telegram.ts](src/lib/telegram.ts), тесты — `e2e/telegram.spec.ts`.
